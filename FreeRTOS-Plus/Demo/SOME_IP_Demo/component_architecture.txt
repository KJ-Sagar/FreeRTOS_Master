## 🔄 Data Flow: Subscription Lifecycle

### **1. Client Subscribes (TCP Method)**
```
Client → SUBSCRIBE(service_id=0x1234, eventgroup_id=0x0001, ttl=5)
  ↓
someip_client_task.c
  ↓
someip_client_subscribe(ctx, 0x1234, 0x0001, 5)
  ↓
Subscription Table Updated:
  - eventgroup_id: 0x0001
  - state: SUBSCRIBED
  - expiry_tick: now + 5 seconds
  ↓
Client ← ACK
```

### **2. Notification Broadcast**
```
someip_notification_task (every 2 seconds)
  ↓
For each client in g_someip_clients:
  For each subscription in client.subscriptions:
    if (state == SUBSCRIBED && not expired):
      if (eventgroup contains event 0x0001):
        send_notification(client.socket, event_data)
```

### **3. TTL Expiration**
```
someip_ttl_manager_task (every 1 second)
  ↓
For each client:
  For each subscription:
    if (current_tick >= expiry_tick):
      subscription.state = EXPIRED
      Log: "Subscription expired for client X eventgroup Y"
```

### **4. Client Unsubscribes**
```
Client → UNSUBSCRIBE(eventgroup_id=0x0001)
  ↓
someip_client_unsubscribe(ctx, 0x1234, 0x0001)
  ↓
Subscription removed from table
  ↓
Client ← ACK
```

## 🎯 Key Improvements Over Phase 3

### **Multi-Client Support**
- ✅ Broadcast notifications to ALL subscribed clients
- ✅ Isolated state per client
- ✅ One client failure doesn't affect others

### **Event Group Abstraction**
- ✅ Services can have multiple event groups
- ✅ Client subscribes to event groups, not individual events
- ✅ Events grouped logically (e.g., "Diagnostics", "Telemetry")

### **TTL Management**
- ✅ Automatic subscription expiration
- ✅ Configurable TTL per event group
- ✅ Renewal on re-subscribe

### **SD Integration**
- ✅ UDP-based SubscribeEventgroup
- ✅ Unicast endpoint options
- ✅ Multicast support (optional)

### **Thread Safety**
- ✅ Mutex-protected subscription tables
- ✅ Safe concurrent access from RX task and notification task

### **Robustness**
- ✅ Buffer overflow protection
- ✅ Malformed message handling
- ✅ Graceful client disconnect cleanup

## 📝 Example: Heartbeat Service with Event Groups

### **Service Definition**
```c
/* Heartbeat service has ONE event group: "Status" */
someip_eventgroup_def_t heartbeat_eventgroup = {
    .service_id = 0x1234,
    .eventgroup_id = 0x0001,
    .events = {
        { .event_id = 0x0001, .eventgroup_id = 0x0001, .update_period_ms = 2000 }
        // Event 0x0001 (heartbeat notification) belongs to eventgroup 0x0001
    },
    .event_count = 1,
    .default_ttl_seconds = 5
};
```

### **Registration (in HeartbeatService_Init)**
```c
void HeartbeatService_Init(void)
{
    /* Register service handler (unchanged) */
    someip_register_service(0x1234, heartbeat_handler);
    
    /* NEW: Register event group */
    someip_eventgroup_register(&heartbeat_eventgroup);
}
```

### **Client Subscription**
```python
# Python client subscribes to eventgroup 0x0001
subscribe_msg = build_subscribe(
    service_id=0x1234,
    eventgroup_id=0x0001,
    ttl=5
)
sock.sendall(subscribe_msg)
```

### **Notification**
```c
/* Notification task checks subscription */
if (someip_client_is_subscribed(ctx, 0x1234, 0x0001)) {
    send_heartbeat_notification(ctx);
}
```

## 📊 Memory Footprint

### **Static Allocation**
- Client table: 4 clients × ~200 bytes = 800 bytes
- Event group registry: 16 definitions × ~100 bytes = 1600 bytes
- Subscription table: 4 clients × 8 subscriptions × 20 bytes = 640 bytes
- **Total: ~3KB additional RAM**

### **Stack Usage**
- someip_ttl_manager_task: 512 words
- No additional heap usage
